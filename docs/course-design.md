# 课程设计：从零基础到可独立完成 Rust 小项目

## 为什么重新组织课程

公开课程不能依赖作者的口头补充、历史学习记录或“学到时再补作业”。学习者拿到的仓库必须已经包含完整路线、每课讲解、练习、测试、提示和 AI 助教接入方式。课程因此采用固定 22 课的线性主线，并在后续课程中反复使用前面的核心知识。

“零基础”指不需要学过其他编程语言。读者只需要会使用基本的文件管理操作；命令行、编辑器、编译器等工具概念会在第一课实际操作前解释。偶尔提供其他语言对照时，对照只是可选补充，不能成为理解正文的必要条件。

## 每课的教学顺序

1. **场景**：先呈现读者能理解的小问题，例如保存一组会变化的数据。
2. **困难**：说明已有办法会造成什么具体问题，不夸大，也不制造伪需求。
3. **概念**：给出术语、中文定义和它存在的理由。
4. **语法**：逐项解释符号和代码行为，而不是只展示可运行结果。
5. **完整示例**：从输入到输出解释数据如何变化。
6. **错误实验**：阅读真实编译器或测试诊断，建立排错方法。
7. **练习**：学习者完成已准备好的脚手架，用测试检查行为。
8. **复盘与巩固**：用自己的话解释概念，再完成一个不同数据或不同边界的任务。

## 22 课路线

- 01～04：程序结构、数据建模、所有权与错误处理。
- 05～08：集合、模块、测试与工程质量。
- 09～12：闭包、迭代器、泛型与 trait（特征/行为接口）。
- 13～15：递归数据结构、生命周期与智能指针。
- 16～19：线程、共享状态、文件命令行与异步任务。
- 20～21：宏与 unsafe/FFI（外部函数接口），重点包括“为什么通常不用”。
- 22：综合命令行数据工具。

高级主题并不意味着必须使用高级方案。课程反复训练根据需求选择简单、可验证的实现。

## 练习与答案边界

所有作业随课程一起发布。主练习通过 `todo!()` 标出学习者负责的部分，测试描述可观察行为。三级提示提前写在 `HINTS.md`，学习者卡住时按级查看，不需要等待作者在线生成。

默认仓库不包含完整参考实现。这样既保留练习价值，也避免 AI 助教在辅导时无意读到并直接泄露答案。维护者需要验证练习时，在临时目录完成实现并运行测试，随后删除临时内容。

## 完成标准

学习者完成 22 课后应能：

- 创建、运行、测试和组织一个中小型 Rust 项目；
- 解释所有权、借用和生命周期解决的具体问题；
- 使用结构体、枚举、集合、错误处理和迭代器建模数据；
- 阅读常见泛型、trait 与并发代码；
- 判断 async、宏和 unsafe 是否真有需求；
- 根据测试和诊断定位问题，而不是盲目复制修改。

# 第 NN 课：用读者能理解的语言写出主题

> 本模板供课程维护者使用。新课还要创建独立 Cargo package、练习源码、自动测试和 HINTS.md，并完成 tools/check_course.py 检查。

## 本课定位

- 从一个具体场景说明本课解决什么问题。
- 说明为什么现在需要它；不要只写“这是重要特性”。
- 列出前置知识，并用一句话复习；链接对应课程。
- 写明本课边界。若提到后课术语，先给当前够用的中文解释。

## 如何学习本课

给出阅读、预测、实验、主练习和课后巩固的顺序，以及预计时间。

## 一、为什么需要这个概念

1. 先展示只有旧知识时会遇到的具体困难。
2. 解释新术语的中文含义和英文写法。
3. 说明 Rust 的方案解决了什么、没有解决什么。

## 二、语法与行为

按小概念分节。每节包含语法、逐行解释、完整可运行示例、适用场景和误区。不能假设读者懂其他编程语言，也不能把通用编程概念当作不言而喻。

## 三、编译器或测试诊断

展示典型错误、关键诊断原文、诊断中术语的解释、根因和修复方向。不要只给修改后的代码。

## 四、完整示例

提供不同于主练习的例子，从输入到输出解释数据和类型的变化。

## 五、代码预测与解析

先给问题，再用折叠区块提供答案和推理过程。

## 六、主练习

### 目标与行为

### 输入、输出与边界

使用真实输入和对应期望输出，至少包含一个边界或错误示例。只界定行为，不泄露实现。

### 脚手架与约束

写出本课 package 名、要修改的文件和必须保留的公共接口。

### 推荐完成顺序

### 测试说明与验收命令

使用统一命令，并说明实现前哪些失败来自 `todo!()`：

```bash
cargo test -p lNN_topic
```

## 七、课后巩固

提供一个不同数据或不同边界的任务。对应脚手架和自动测试必须已经存在，并给出具体验收命令。

## 八、常见误区

解释错误原因和适用边界，不只列禁止事项。

## 九、本课总结

用完整句子总结长期有用的模型，不引入未解释的新术语。

## 十、课后复盘

让读者用自己的话解释“为什么需要它”“规则是什么”“如何判断错误”。

## 下一课预告

说明本课知识会在下一课解决什么新问题。

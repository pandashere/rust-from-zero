# 第一课提示：主练习与课后巩固

卡住时按级别查看：提示 1 只给思考方向，提示 2 把问题拆小，提示 3 给出接近完整的结构。请尽量在最低的级别解决问题——直接看提示 3 会拿走你自己组织代码的练习机会。

每一级提示都不会贴出完整可运行的答案。看完提示后回到 `src/exercise.rs` 或 `src/consolidation.rs`，用 `cargo test -p l01_basics` 检查。

## 主练习一：`clamp`

### 提示 1：思考方向

返回值只有三种可能：下界、上界、原值。这三种可能分别对应三种大小关系。想一想：用本课学过的哪种语法，可以把“三种情况各得到一个值”写成一个整体的值，直接作为函数的返回结果？

### 提示 2：局部分解

- 先判断 `value` 和 `minimum` 的关系，命中时整个表达式的值是 `minimum`。
- 否则再判断 `value` 和 `maximum` 的关系，命中时值是 `maximum`。
- 两个条件都不命中时值是 `value`。
- 注意“恰好等于某一端”属于第三种情况，所以比较时用严格小于、严格大于即可，不需要 `<=` 或 `>=`。

### 提示 3：接近完整的结构

```rust
if value < minimum {
    minimum
} else if /* value 和 maximum 的关系 */ {
    // 这个分支该得到什么值？
} else {
    // 剩下的情况该得到什么值？
}
```

整个 `if / else if / else` 是函数体的最后一个表达式，不要在任何分支末尾加分号，也不需要 `return`。

## 主练习二：`sum_inclusive`

### 提示 1：思考方向

区间求和需要“逐个访问、逐个累加”。先想清楚两件事：循环开始前需要记住哪些状态？每一轮循环结束时，这些状态分别发生了什么变化？空区间为什么可以不动手写特判——循环条件本身能不能天然地一次都不执行？

### 提示 2：局部分解

- 准备两个可变的量：一个表示“当前加到哪个数”，从 `start` 出发；一个表示“到目前累加的结果”，从 `0` 出发。
- 循环的继续条件只和“当前数”与 `end` 的大小关系有关；想清楚等于 `end` 的那一轮要不要执行（区间是闭区间）。
- 每轮循环做两件事：把当前数并入结果；让当前数向后移动一步。
- 空区间时继续条件一开始就不成立，循环体一次都不执行，结果自然就是初始的 `0`。

### 提示 3：接近完整的结构

```rust
let mut current = start;
let mut total = 0;
while /* current 还没有越过 end */ {
    // 把 current 并入 total
    // 让 current 前进 1
}
total
```

两个变量都需要 `mut`，因为它们每轮都会被重新赋值。函数最后不要写成分号结尾。

## 主练习三：`count_multiples`

### 提示 1：思考方向

它和 `sum_inclusive` 的循环骨架几乎一样，区别只有两点：每轮不是“累加当前数”，而是“满足某个条件时计数加一”；另外还有两种输入要直接返回 `0`，其中一种必须在任何取余运算之前处理。想一想为什么 `%` 或 `/` 遇到除数 `0` 不能让程序走到那一步。

### 提示 2：局部分解

- 函数一开头先处理两种没有统计对象的情况：区间为空、除数为零。这两种情况都可以用一个提前的 `return 0` 结束函数。
- 计数变量不会为负，可以把它的类型直接定为 `u32`，和返回类型一致。
- 循环骨架与 `sum_inclusive` 相同：当前数从 `start` 走到 `end`。
- 每轮用 `current % divisor == 0` 判断是否整除；这个判断本身是 `bool`，可以用一个 `if` 决定是否给计数加一。

### 提示 3：接近完整的结构

```rust
if divisor == 0 || start > end {
    return 0;
}
let mut current = start;
let mut count: u32 = 0;
while /* current 还没有越过 end */ {
    if /* current 能被 divisor 整除 */ {
        // count 加一
    }
    // 让 current 前进 1
}
count
```

顺序很重要：先做非法输入判断，再进入任何含 `%` 的代码。

## 巩固任务一：`collatz_steps`

### 提示 1：思考方向

这是一个“不知道要循环多少轮”的问题：循环次数本身就是要算的答案。每一轮只依赖当前数字，所以需要一个变量保存“当前数字”，另一个变量保存“已经变换了几次”。想一想：哪一类循环天然适合“次数未知、由条件决定”的场景？

### 提示 2：局部分解

- 先处理两种特殊情况：`start == 0` 直接返回 `0`；`start == 1` 时循环条件一开始就不成立，次数自然是 `0`，通常不需要为它单独写分支。
- 循环继续的条件是“当前数字还不是 `1`”。
- 每轮先按奇偶规则更新当前数字，再把次数加一。注意顺序：变换一次，计一次。
- 更新当前数字时，奇偶判断用 `current % 2 == 0`。

### 提示 3：接近完整的结构

```rust
if start == 0 {
    return 0;
}
let mut current = start;
let mut steps = 0;
while /* 还没到 1 */ {
    // 偶数时 current 变成它的一半；奇数时变成 3 * current + 1
    // steps 加一
}
steps
```

## 巩固任务二：`sum_of_digits`

### 提示 1：思考方向

你不可能直接看到“每一位数字”，但 `% 10` 能取出十进制的最后一位，`/ 10` 能去掉最后一位。反复做这两件事，直到没有数字剩下。负数怎么办？函数开头先把它变成和正数一样的形式。

### 提示 2：局部分解

- 开头先得到一个非负的工作数字：`if value < 0 { -value } else { value }`。
- 循环继续的条件是“工作数字还不为 `0`”。
- 每轮做三件事：取出最后一位并入总和；把工作数字去掉最后一位；等待下一轮。
- `0` 的数位之和自然是 `0`——检查你的循环在初始值是 `0` 时是否正好一次都不执行。

### 提示 3：接近完整的结构

```rust
let mut remaining = /* value 的非负形式 */;
let mut total: u32 = 0;
while remaining > 0 {
    // remaining % 10 是最后一位，并入 total（注意类型）
    // remaining / 10 去掉最后一位
}
total
```

`remaining % 10` 的类型是 `i32`，而 `total` 是 `u32`，并入时需要一次显式的类型转换；这一位不可能是负数，所以转换是安全的。

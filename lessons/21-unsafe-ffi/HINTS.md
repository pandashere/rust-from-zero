# 第二十一课提示（HINTS）

卡住时按级别查看：第一级只给思考方向，第二级把问题拆小，第三级给出接近完整的结构。

尽量在看完某一级后回到代码里再试一次，而不是一次读完三级。提示不直接给出完整答案；如果你发现自己只是在照抄第三级，先合上屏幕，用自己的话把“需要证明什么”复述一遍再写。

写 `unsafe` 块时，SAFETY 注释至少回答：

1. 调用了哪个要求前置条件的 API？
2. 该 API 文档要求哪些条件？
3. 代码里的哪个检查或类型保证，分别对应这些条件？
4. 生命周期、空切片、越界和 panic 路径是否也保持条件？

## 主练习第一部分：`split_at_mut_checked`（`src/exercise.rs`）

### 第一级（思考方向）

你要交给调用者两个可写的切片借用，而编译器只看到一个 `&mut [T]`。先问自己：

- 在构造任何切片之前，哪个运行时条件必须先检查？如果不检查，`mid` 很大时会发生什么？
- 输入切片本身能提供哪些已经成立的事实（起始地址、长度、元素已初始化、借用有效期）？
- 第二个切片的起始位置应该从第一个位置偏移多少个**元素**？
- 两个切片的长度分别是什么？它们加起来是否正好覆盖原切片且不重叠？

### 第二级（局部分解）

1. 先用 `values.len()` 取到长度，比较 `mid` 和长度；越界直接返回 `None`，不要先碰指针。
2. 用 `values.as_mut_ptr()` 取得起始裸指针。它来自一个有效的 `&mut [T]`，所以非空、对齐，并且指向已初始化的元素。
3. 前段从起始指针开始，长度是 `mid`。
4. 后段从起始指针向后移动 `mid` 个元素的位置开始，长度是 `len - mid`。
5. 两个 `from_raw_parts_mut` 调用放在同一个 `unsafe` 块里，然后组成 `Some((前段, 后段))` 返回。
6. 不需要手写生命周期参数：返回类型省略了生命周期，编译器会把它和输入的 `&mut [T]` 关联起来。
7. 在 `unsafe` 上方写 SAFETY 注释，分别说明：指针非空对齐、两段在同一分配内、两段不重叠、元素已初始化、借用期不重叠。

### 第三级（接近完整的结构）

```text
如果 mid 大于 values 的长度:
    返回 None

记录 len = values 的长度
记录 p = values 的起始可变裸指针

在 unsafe 块里:
    前段 = 从 p 开始、长度为 mid 的可变切片
    后段 = 从“p 向后移动 mid 个元素”开始、长度为 len - mid 的可变切片
    返回 Some((前段, 后段))
```

检查 SAFETY 注释是否覆盖了 `mid == 0`、`mid == len` 和空切片这三种边界。它们都应该自然成立，不需要额外分支。

## 主练习第二部分：`count_byte`（`src/ffi.rs`）

### 第一级（思考方向）

C 函数不知道 Rust 切片是什么，它只要“起始地址 + 长度 + 目标字节”。先看 `src/ffi.rs` 顶部的 `unsafe extern "C"` 声明：

- 三个参数分别对应 `&[u8]` 的什么信息？
- 调用期间，C 端承诺只读；Rust 端的共享借用能保证哪些事？
- `unsafe` 应该只包住哪一件事？

### 第二级（局部分解）

1. `&[u8]` 同时带有起始地址和长度：`data.as_ptr()` 给出地址，`data.len()` 给出长度。
2. `needle` 原样作为第三个参数。
3. 在 `unsafe` 块里调用 `ffi.rs` 中声明的 C 函数，把三个值按顺序传进去。
4. 返回值就是出现次数，直接返回它。
5. 写 SAFETY 注释：`as_ptr()`/`len()` 描述的正是这块存活的切片；`u8` 对齐要求为 1；共享借用保证调用期间没有可变访问；C 端不保存指针。

### 第三级（接近完整的结构）

```text
在 unsafe 块里调用 C 端声明:
    参数一 = data 的起始地址
    参数二 = data 的长度
    参数三 = needle
把调用的返回值直接作为函数结果
```

注意：不需要自己检查空切片。空切片的 `as_ptr()` 仍然是非空、对齐的地址，长度 0 也在 C 契约允许范围内。

## 课后巩固：`read_c_name`（`src/consolidation.rs`）

### 第一级（思考方向）

这个函数拿到的是一个裸指针，可能为空，也可能指向以 NUL 结尾的字节。分两步想：

- 哪一步必须在进入 `unsafe` 之前完成，否则连“读内存”都不该开始？
- 得到 C 字符串视图后，Rust 需要验证什么才能把它变成 `String`？失败时应该返回哪个错误变体？

记住：函数返回的是拥有型 `String`，不是借用。

### 第二级（局部分解）

1. 先判断 `pointer.is_null()`；为空就返回 `Err(NameError::NullPointer)`，不读任何内存。
2. 在 `unsafe` 块里用 `CStr::from_ptr` 把指针变成 `&CStr`。这一步依赖调用者保证指针有效且以 NUL 结尾，所以函数本身是 `unsafe fn`。
3. `&CStr` 上有 `to_str()`，它检查 UTF-8：成功得到 `&str`，失败得到 UTF-8 错误。
4. 成功时把 `&str` 复制成拥有型 `String`（例如使用 `to_owned` 或 `to_string`）。
5. 失败时用 `map_err` 或 `match` 转成 `NameError::NotUtf8`。
6. SAFETY 注释写在 `from_ptr` 调用旁，说明调用者契约和空指针检查的顺序。

### 第三级（接近完整的结构）

```text
如果 pointer 是空指针:
    返回 Err(NameError::NullPointer)

在 unsafe 块里:
    把 pointer 变成借用的 C 字符串视图 &CStr

把 &CStr 转成 &str:
    成功 -> 复制成 String，返回 Ok
    失败 -> 返回 Err(NameError::NotUtf8)
```

检查两个容易漏的点：

- 空指针检查必须在 `unsafe` 之前，且空指针路径不读取任何字节；
- 返回的必须是拥有型 `String`，不能把 `&str` 的借用直接返回，否则原 `CString` 销毁后会悬垂。

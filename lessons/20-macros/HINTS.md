# 第二十课提示：主练习与课后巩固

提示分三级，卡到哪一级看哪一级：

- **一级：思考方向**——只提示该想什么，不涉及可以直接粘贴的代码。
- **二级：局部分解**——把任务拆成几个步骤，指出每一步要用的语法工具。
- **三级：接近完整的结构**——给出带空缺的骨架，你需要自己补上捕获变量和展开内容。

先看一级；想清楚了就不要继续往下看。三级提示故意保留空缺，不是完整答案。
看完提示后，用 README 里给出的单条测试命令缩小范围，例如：

```bash
cargo test -p l20_macros stock_builds_items_with_explicit_quantities
```

## 主练习：`stock!`（`src/exercise.rs`）

### 一级：思考方向

先数一数调用形式有几种：空清单、写明数量、只写名字。每种形式在**逗号、
箭头、尾逗号**上的形状是否相同？宏的规则是整段匹配的，所以不同形状通常
需要不同的规则。

然后想：展开后要得到什么类型？每一项应该调用哪个构造函数？这个构造函数
在 `exercise` 模块里，而宏可能被别的 crate 调用，展开模板应该用哪种路径
写法才能不依赖调用处？

最后检查求值次数：你写出的模板里，一个 `$name` 或 `$quantity` 出现了几次？
出现两次就会求值两次。

### 二级：局部分解

1. 三条规则按“最具体到最宽松”的顺序排列：先写空清单，再写带 `=>` 的形式，
   最后写只有名字的形式。空清单不能落入后面用 `+` 的规则，因为 `+` 要求
   至少一项。
2. 空清单直接返回一个空的库存清单。空 `Vec` 的元素类型由调用处的期望类型推断，
   测试里写作 `let items: Vec<StockItem> = stock![];`，所以 `Vec::new()` 可以工作。
3. 带 `=>` 的规则里，对每一组捕获重复“构造一个 `StockItem` 并放进清单”。
   可以用标准库的 `vec!` 宏一次性写出清单，也可以在块里创建 `Vec` 再逐项
   追加；两种都可以，但都要保证每个捕获只出现一次。构造时使用
   `$crate::exercise::StockItem::new(...)`，第一个参数是名字捕获，第二个
   是数量捕获。
4. 只有名字的规则结构相同，只是数量位置写固定的默认值 `1`。
5. `$(,)?` 已经在匹配模式里，负责吞掉可选的尾逗号；展开模板不需要为它
   再写任何东西。

### 三级：接近完整的结构

```rust
#[macro_export]
macro_rules! stock {
    () => {{
        /* 返回空清单的表达式 */
    }};
    ($($name:expr => $quantity:expr),+ $(,)?) => {{
        ::std::vec![
            $(
                /* 用 $crate 路径构造 StockItem；两个捕获分别放在哪里？ */
            ),+
        ]
    }};
    ($($name:expr),+ $(,)?) => {{
        ::std::vec![
            $(
                /* 结构同上，但数量使用什么固定值？ */
            ),+
        ]
    }};
}
```

如果 `cargo test` 报“no rules expected ...”，先回到一级，对照调用写法和
三条规则的逗号、箭头位置，而不是急着改展开模板。

## 主练习：`ensure!`（`src/exercise.rs`）

### 一级：思考方向

这个宏不是在“计算一个值”，而是要让**调用它的那个函数**提前结束。想一想：
Rust 里哪个关键字能从当前函数立刻返回？返回值的 `Err(...)` 部分来自宏的
哪个捕获？

再想求值顺序：条件为真时，错误表达式应不应该被计算？怎样写才能让错误
表达式只出现在“失败”那条路径上？

### 二级：局部分解

1. 判断条件是否**不成立**。条件本身只读取一次，不要先把它存起来再判断，
   也不要写两遍。
2. 条件不成立时，展开出一条 `return` 语句：返回 `Err(...)`，括号里直接放
   错误表达式捕获。
3. 条件成立时什么也不做，让调用者函数继续执行宏调用之后的语句。
4. 匹配模式里的 `$(,)?` 负责可选的尾逗号，展开时不用处理它。
5. 注意：`return` 写在宏展开里，结束的是**调用宏的函数**，不是宏自己。
   这也是为什么 `take_stock` 能在检查失败后不再执行后面的减法。

### 三级：接近完整的结构

```rust
#[macro_export]
macro_rules! ensure {
    ($condition:expr, $error:expr $(,)?) => {
        if /* 条件在什么情况下算失败？ */ {
            /* 让当前函数立即返回；错误值来自哪个捕获？ */
        }
    };
}
```

## 课后巩固：`matrix!`（`src/consolidation.rs`）

### 一级：思考方向

这个宏有两层重复：外层重复“行”，内层重复“一行里的数字”。先分别问：
外层用什么分隔？内层用什么分隔？哪一层允许空（零个数字）？

空行和空表是两种不同的情况：`matrix![]` 没有任何行，`matrix![[]]` 有一行，
但这一行没有数字。匹配模式要能区分它们。

尾逗号也有两层：每个 `[...]` 内部最后可以有一个逗号，整个调用最后也可以
有一个逗号。匹配模式里需要两个独立的 `$(,)?`。

### 二级：局部分解

1. 第一条规则处理完全没有内容的情况，返回空的二维清单。
2. 第二条规则的外层是“一个或多个方括号行”，用 `+`。每一行内部的数字用
   `*`，因为一行可以没有数字；行内数字之间用逗号分隔，并允许一个可选
   尾逗号。
3. 展开时，外层重复为每一行构造一个 `Vec<i64>`；内层重复把该行的每个
   数字放进这个 `Vec`。可以嵌套使用标准库的 `vec!`，让结构更直观。
4. 因为数字是任意 `expr`，每个捕获在展开中只能出现一次，否则带副作用的
   表达式会被执行多次。
5. 空表规则必须放在最前面；否则 `matrix![]` 没有任何一条规则能匹配，
   会得到“no rules expected”一类错误。

### 三级：接近完整的结构

```rust
#[macro_export]
macro_rules! matrix {
    () => {{
        /* 返回空二维清单的表达式 */
    }};
    ($([$($value:expr),* $(,)?]),+ $(,)?) => {{
        ::std::vec![
            $(
                ::std::vec![
                    /* 内层重复：每个 $value 怎样进入这一行？ */
                ]
            ),+
        ]
    }};
}
```

## 通用排错顺序

1. 先只跑一条测试，例如 `cargo test -p l20_macros matrix_accepts_empty_rows`，
   避免一次面对十几个失败。
2. 如果是 `no rules expected ...`，先检查调用写法与匹配模式的逗号、方括号、
   箭头；这条错误通常与展开模板无关。
3. 如果是 `meta-variable ... repeats ... times`，把匹配模式和展开模板的
   重复层级并排写出来，确认每个捕获在展开时处于相同的重复层。
4. 如果测试不 panic 但断言失败，检查顺序、默认值、空行/空表等边界，而不是
   先怀疑测试。
5. 不要修改测试和函数签名来“让测试通过”；测试描述的是要求的行为。
